What is an AI or automation stack?

A tool normally performs a particular job. A stack combines several tools and technologies so that different parts of a larger process can work together.

For example, one tool might collect information, another might store it, AI might interpret it, automation might move it to another application, and a final tool might deliver the result.

The purpose isn't to own lots of software. The purpose is to connect the right capabilities around a useful outcome.

Stack · Input

Where does the stack begin?

Input is whatever starts the process or provides the information the stack needs.

It could be a form submission, customer message, payment, document, database record, scheduled event or another workflow trigger.

Understanding the input is important because the rest of the stack exists to do something useful with it.

Stack · Tools

Give every tool a clear job.

Tools are the practical capabilities inside a stack. One might handle data, another content, another payments and another customer communication.

The goal isn't to use the most popular tools. The goal is to choose tools that solve the actual requirements of the process.

Stack · AI

Where does AI fit?

AI can provide capabilities that are difficult to handle with simple fixed rules.

Depending on the stack, AI might summarise information, classify an enquiry, generate content, extract information from documents or help determine what should happen next.

AI doesn't automatically need to control the entire process. Often it is simply one useful component.

Automation connects the pieces.

Automation can move information between applications, trigger the next stage and perform predictable actions.

For example, a customer enquiry could enter through a form, be classified by AI, stored in a CRM and then trigger a follow-up email.

Build your own

How do you build an AI or automation stack?

Don't start by asking which tools you should buy. Start by defining the outcome you want.

Then work backwards.

  1. Define the outcome.
  2. Identify the information entering the process.
  3. Break the job into individual steps.
  4. Decide which steps need normal software.
  5. Decide where AI provides a useful capability.
  6. Identify which predictable steps can be automated.
  7. Decide where human review is necessary.
  8. Choose tools that fit those requirements.

Important

More tools doesn't mean a better stack.

It can be tempting to keep adding AI tools, automation platforms and software because each one looks useful.

But every additional component can introduce cost, maintenance, complexity and another point of failure.

A good stack is not the biggest stack. It's the simplest collection of components that can reliably achieve the required outcome.
