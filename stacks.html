Stacks

Tools work better together.

A technology stack is a collection of tools, AI, automation and other technologies connected together to achieve a specific outcome.

Start here

What is an AI or automation stack?

A tool normally performs a particular job. A stack combines several tools and technologies so that different parts of a larger process can work together.

For example, one tool might collect information, another might store it, AI might interpret it, automation might move it to another application, and another tool might deliver the result.

The purpose isn't to own lots of software. The purpose is to connect the right capabilities around a useful outcome.

02 · Stack

A stack connects the jobs.

Imagine you want to produce and publish content. You might need research, writing, image or video creation, voice generation, storage and publishing.

Those capabilities can be provided by different tools. When they're deliberately connected around the same outcome, they form a stack.

The stack is therefore about the relationship between the tools, not simply the list of tools itself.

03 · System

A system makes the stack useful repeatedly.

A collection of tools isn't automatically a system. A system describes the process, rules, connections, responsibilities and outcomes that make the technology useful.

This is where a stack becomes more than a list of software. It becomes part of a repeatable way of working.

Stack · Input

Where does the stack begin?

Input is whatever starts the process or provides the information the stack needs.

It could be a form submission, customer message, payment, document, database record, scheduled event or another workflow trigger.

Understanding the input is important because the rest of the stack exists to do something useful with it.

Stack · Tools

Give every tool a clear job.

Tools are the practical capabilities inside a stack. One might handle data, another content, another payments and another customer communication.

The goal isn't to use the most popular tools. The goal is to choose tools that solve the actual requirements of the process.

Explore Tools →
Stack · AI

Where does AI fit?

AI can provide capabilities that are difficult to handle with simple fixed rules.

Depending on the stack, AI might summarise information, classify an enquiry, generate content, extract information from documents or help determine what should happen next.

AI doesn't automatically need to control the entire process. Often it is simply one useful component.

Stack · Automation

Where does automation fit?

Automation is particularly useful when the steps are predictable. It can trigger actions, move information between applications and connect different services.

For example:

Form submission → database → AI analysis → email → notification

Automation can therefore act as the connective layer between the different components of a stack.

Stack · Output

What should the stack produce?

Every stack should have a clear outcome. The output might be a published article, qualified lead, customer response, report, database record, product or completed workflow.

If you cannot clearly describe the desired output, it becomes much harder to decide which tools belong in the stack.

Where agents fit

Agents can become one component of a stack.

An agent doesn't replace the entire stack. It can become one part of a larger system where flexible decision-making is useful.

For example:

Input → Agent → Tools → Automation → Human approval → Output

The agent may interpret the goal, decide which tool is useful and adapt to the results. Automation can then handle predictable parts of the process.

Build deliberately

How to build a useful stack.

01

Start with the outcome.

Define what the stack needs to achieve before choosing software.

02

Map the process.

Break the outcome into the major steps and identify what each step requires.

03

Choose capabilities.

Decide which parts require a tool, AI, automation, human judgement or another capability.

04

Choose the tools.

Only then compare software based on what the process actually needs.

05

Connect the pieces.

Build the workflow and make sure information can move correctly between the components.

06

Test the result.

Check whether the complete stack actually produces the desired outcome before adding more complexity.

Important

More tools do not make a better stack.

One of the easiest mistakes is adding software simply because it looks useful.

Every additional component creates another connection, another dependency and another thing that can fail.

A strong stack is usually built around a clear outcome with the fewest components necessary to achieve it reliably.
